VTJ funnel measurement definitions
==================================

These definitions keep intent clicks separate from completed inquiries and operational outcomes.

- Contact intent — `contact_channel_click`: count when a visitor opens WhatsApp, LINE, or email. Do not count it as a lead or inquiry.
- Booking intent — `booking_cta_click`: count when a visitor opens a booking/request path or selects a vehicle from results. Do not count it as a submitted request.
- Search results — `view_search_results`: count when date-based vehicle results render. Do not report the available vehicle count when `availability_complete` is false.
- Quote request — `quote_request_submitted`: count only when `/api/quote` returns success. Do not count a mail-client fallback or button click.
- Booking request — `booking_request_submitted`: count only when `/api/booking` returns a booking ID. Do not count it as a confirmed booking.
- Booking form view/start — `booking_form_view` fires when the form loads; `booking_form_start` fires once on the first user edit.
- Booking step — `booking_step_completed` fires after step 1 validates; `booking_step_viewed` records navigation to each later step.
- Validation — `booking_validation_error` records only the step and number of invalid fields. It must not include entered values.
- Availability — `availability_check_result` records available, conflict, confirmation needed, or request failed, plus vehicle and rental duration. It must not include exact dates.
- Vehicle choice — `booking_vehicle_selected` records the vehicle slug and rental duration.
- Submit attempt/failure — `booking_request_attempted` records an attempt and optional-field presence; `booking_request_failed` records API or network failure. Neither event contains entered values.
- Booking WhatsApp exit — `booking_whatsapp_clicked` records CTA placement, vehicle and rental duration. It remains an intent event, not a lead.
- General GA4 lead — `generate_lead`: count only when a quote, booking, or contact form returns success. Do not fire it for WhatsApp, LINE, or email clicks.
- Confirmed booking — D1 `bookings.status = confirmed`: count when Karen has confirmed the booking under the operating procedure. A form submission alone is insufficient.
- Paid booking — D1 payment record/status: count only after payment has been verified. Sending a payment link is insufficient.
- Rental completed — D1 `bookings.status = completed`: count after the vehicle has been returned and the rental closed. Do not count future confirmed revenue here.

Use `booking_id` as the booking-form reconciliation key. Channel conversations without a booking ID must be matched to one operational record before they count as confirmed or completed. Deduplicate repeated events by booking ID for booking requests and by the operational record for downstream revenue reporting.

GA4 reports describe the online funnel. D1 remains the source of truth for confirmed bookings, payments, actual rental days, cancellations, refunds, and revenue.

Date searches are also written to the privacy-safe D1 `rental_searches` table through `POST /api/demand`. This operational log captures requested dates, party size, compatible/available vehicle counts and coarse attribution. It never stores contact details, raw IP addresses, user agents, gclid values or WhatsApp text. Use authenticated `GET /api/admin/demand-summary?days=90` for aggregated pricing and capacity analysis.

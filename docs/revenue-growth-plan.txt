# VanTripJapan 年商2,000万〜3,000万円 実行計画

更新日: 2026-09-13

## 目標の定義

この計画では、レンタル売上の年間合計を年商として扱う。消費税、返金、決済手数料、整備費、清掃費、保険料、車両償却を含む利益とは分けて管理する。利益率を判断するには、これらの原価を月次で追加する必要がある。

最初の目標は年商2,000万円を安定して再現すること。3,000万円は、現行3台だけで無理に稼働率や価格を上げず、増車または付帯売上を含む供給計画として扱う。

## 供給能力から見た現実的な範囲

現行の平日基本料金はProbox ¥22,000、Bongo ¥22,000、Pocket Loft ¥25,000。週末1.5倍を均等な一週間に当てはめると、3台合計の理論上限は年間約2,878万円になる。これは365日すべて貸し出し、整備停止、空車、長期割引、キャンセルを一切含めない数字である。

次の試算では、長期割引などによる平均7%の値引きを仮定する。季節料金、オプション売上、整備停止は含めない。

| 3台の年間稼働率 | 試算年商 | 判断 |
|---:|---:|---|
| 65% | 約1,740万円 | 現実的な下限シナリオ |
| 70% | 約1,874万円 | 2,000万円まで約126万円不足 |
| 75% | 約2,008万円 | 2,000万円到達ライン |
| 80% | 約2,141万円 | 高稼働。整備余力の確認が必要 |
| 85% | 約2,275万円 | 継続運用には負荷が高い |

3台で3,000万円は、値引きや整備停止を考える前の理論上限も超えるため、持続可能な目標ではない。3,000万円には次のいずれかが必要になる。

- 4台体制で80%前後の高稼働を作り、季節料金または利益の出る付帯商品を組み合わせる。
- 5台体制で稼働率を65〜70%程度に抑え、故障や清掃の余力を持つ。
- レンタル以外の粗利が高い売上を年500万〜800万円作る。

増車判断は、需要データ上で満車による失注が3か月続き、既存車両の整備時間を除く稼働率が75%を超えてから行う。

## 成長の順序

### 1. 計測と予約漏れをなくす（0〜30日）

- レンタル検索、車両選択、予約開始、予約送信、問い合わせ経路を同じ定義で計測する。
- WhatsApp、Gmail、フォームの全問い合わせを、個人情報を入れない問い合わせ結果台帳へ当日中に記録する。
- 満車、価格、車両不適合、日程変更、無返信などの失注理由を必須にする。
- 検索需要と問い合わせ結果を月別に照合する。検索数だけを需要とみなさない。

完了条件は、問い合わせ件数と予約台帳の差が毎週0件になり、主要な失注の80%以上に理由が付いていること。

### 2. 現行流入のCVRを上げる（15〜60日）

- 記事から日付・人数を入れて実在庫と料金を確認できる導線を使う。
- 車両カードでは定員、就寝方法、荷物、向いている旅行を同じ順序で比較できるようにする。
- 予約申請は日程・車両、氏名・メールの2段階を中心にし、免許や追加装備は補足欄へ置く。
- 在庫確認不能時は「空車」と断定せず、確認が必要と表示する。
- 問い合わせ初回返信の中央値を営業時間内30分以内、最長24時間以内にする。

CVRは全体平均だけでなく、言語、端末、流入ページ、希望月、人数、車種で分ける。母数が30件未満の区分では結論を出さない。

### 3. 価格を小さく検証する（45〜120日）

価格変更は新規見積もりだけに適用し、合意済み・予約済みの金額は変更しない。最低限、対象月に検索10件、問い合わせ3件があることを条件にする。

| 状況 | 推奨アクション |
|---|---|
| 満車検索40%以上、成約3件以上、価格失注30%未満 | 新規見積もりで+10%を2週間テスト |
| 満車検索25%以上、成約2件以上、価格失注30%未満 | 新規見積もりで+5%を2週間テスト |
| 価格理由の失注30%以上 | 値上げを止め、価格説明と商品構成を検証 |
| 平均空車1.5台以上、成約率25%未満 | 価格を維持し、返信速度と提案内容を改善 |
| 検索10件未満または問い合わせ3件未満 | 現行価格を維持し、データを蓄積 |

テスト中止条件は、対象月の成約率が直前期間より20%以上悪化する、価格失注率が30%を超える、または問い合わせ数が少なすぎて判定できない場合。値下げは、車両1日あたりの限界利益が設定されるまで自動提案しない。

### 4. 2,000万円を安定させる（90〜240日）

- 月ごと、車種ごとの整備可能日を除いた稼働率を管理する。
- 閑散月は一律値下げより、日程の前後提案、車種変更、長期滞在向けの価値説明を先に試す。
- 繁忙月は+5%から始め、成約率と価格失注を見ながら最大+15%まで段階的に検証する。
- 7日、14日、21日の割引は稼働率ではなく総粗利で評価する。
- キャンセル後に再販できなかった日数を記録し、キャンセル規定と再販売施策を調整する。

3か月移動平均で年換算2,000万円を超え、満車失注、整備停止、返信時間が悪化していなければ次段階へ進む。

### 5. 3,000万円の供給を作る（180〜365日）

- 満車失注が多い人数・就寝構成に合う車両を増やす。
- 増車前に、車両購入、改装、保険、駐車、整備、清掃の年間原価を含む投資回収月数を算出する。
- 付帯商品はETC通行料のような立替金と分け、粗利が測れる装備、配送、旅程支援などだけを売上施策として評価する。
- 4台体制で3,000万円を狙う場合は、80%前後の稼働に加えて季節料金または付帯粗利が必要になる。運用負荷が高ければ5台体制を優先する。

## 毎週見る数字

| 領域 | 指標 | 用途 |
|---|---|---|
| 集客 | 記事別のレンタル検索開始率 | 売上につながる記事を判定 |
| 検索 | 検索数、満車率、対応外人数率 | 価格と車両構成を判断 |
| 予約 | 検索→車両選択→申請開始→送信のCVR | 離脱箇所を特定 |
| 対応 | 初回返信時間、24時間超過件数 | 手作業の予約漏れを防止 |
| 成約 | 問い合わせ、成約、失注理由 | 本当の需要を判定 |
| 稼働 | 車種別の貸出日、整備停止日、空車日 | 供給能力を把握 |
| 売上 | 合意額、返金、付帯売上 | 実売上を把握 |
| 利益 | 清掃、整備、保険、決済、車両原価 | 値下げと増車を判断 |

## 月次の意思決定

1. 予約台帳と問い合わせ台帳の件数差を解消する。
2. 満車失注と価格失注を希望月別に確認する。
3. 料金判断アシスタントの候補を、人が成約内容と運用負荷まで確認する。
4. 価格テストは1か月・1車種・1変更に絞る。
5. テスト前後で成約率、平均単価、粗利、満車率を比較する。
6. 結果を料金カレンダーへ反映し、サイト、予約画面、サーバ見積もりが同額になることを確認する。

## 現時点の優先順位

1. 問い合わせ結果を毎日記録し、最低4週間の基準値を作る。
2. 記事→日程検索→車両選択→予約申請の離脱率を言語・端末別に確認する。
3. 満車の多い月だけ+5%テストを始める。
4. 3か月連続で稼働率75%超かつ満車失注が続いたら増車採算を作る。
5. 年商2,000万円の3か月移動平均が安定してから、3,000万円向けの供給投資を決める。
